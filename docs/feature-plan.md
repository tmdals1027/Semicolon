# 기능 설계 초안

Figma의 스카이 블루 파스텔 페이지를 바탕으로 정리했습니다.
일부 공개와 운영진 승인 방식은 확정했습니다. 기능별 세부 동작과 담당자 권한은 아래 초안을 바탕으로 구체화합니다.

## 확정한 공개 범위와 가입 방식

| 이용자 | 이용할 수 있는 범위 |
| --- | --- |
| 로그인하지 않은 방문자 | 학회 소개, 공개 활동, 모집·가입 안내와 가입 신청 |
| 가입 신청 후 승인 대기 중인 이용자 | 승인 대기 안내와 공개 영역. 내부 회원 기능은 이용할 수 없음 |
| 운영진에게 승인받고 로그인한 학회원 | 내부 일정, 회의록, 자료실, 본인 회비 내역 |
| 담당 권한이 있는 운영진 | 회원 승인, 게시물 관리, 회비 확인·정산 관리 등 맡은 기능 |

- 회원가입은 **가입 신청 → 승인 대기 → 운영진 승인 → 회원 기능 이용** 순서입니다.
- 로그인 전에는 학회 소개 중심의 공개 홈을 보여줍니다.
- Figma의 회비·회의록·일정 중심 홈은 승인된 학회원을 위한 회원 홈으로 구성합니다.
- 활동 사진 등은 공개용으로 지정한 콘텐츠만 공개 영역에 표시합니다.
- 로그인한 상태만으로 내부 기능을 허용하지 않습니다. 서버에서 회원 승인 상태와 해당 기능의 권한을 확인합니다.
- 개인 회비 내역은 본인과 담당 권한이 있는 운영진만 조회합니다.

## 확정한 가입 신청 정보

가입 신청에서 입력받을 필수 정보는 다음 네 가지입니다.

| 항목 | 사용 목적 | 설계 원칙 |
| --- | --- | --- |
| 이름 | 운영진이 신청자를 확인하고 회원 화면에 표시 | 실명 입력. 공개 영역에 자동 노출하지 않음 |
| 학번 | 운영진이 학회원 여부를 확인 | 문자열로 관리. 앞자리 0을 보존하며 학교별 형식은 추후 결정 |
| 이메일 | 계정 연락과 본인 확인에 사용 | 이메일 형식 확인. 로그인 식별자와 소유 확인 절차는 추후 결정 |
| 비밀번호 | 로그인 시 본인 인증 | 원문을 저장하지 않고 비밀번호 해시로 저장. 운영진 화면과 API 응답에 원문이나 해시를 포함하지 않음 |

- 가입 신청을 제출하면 승인 대기 상태로 저장합니다.
- 신청 시각과 승인 상태는 시스템이 기록하는 정보이며, 사용자가 직접 입력하지 않습니다.
- 담당 운영진의 신청 확인 화면에는 이름·학번·이메일·신청 시각·승인 상태를 표시합니다.
- 비밀번호 확인 입력란이 필요하면 화면에서 일치 여부만 검사하고 별도 회원 정보로 저장하지 않습니다.
- 비밀번호 저장은 [Spring Security의 PasswordEncoder 안내](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)를 기준으로 구현 단계에서 구체화합니다.

## 기능별 세부 설계 초안

| 기능 | 화면에 필요한 정보 | 먼저 결정할 내용 |
| --- | --- | --- |
| 홈 | 공개 홈의 학회 소개·공개 활동·가입 안내, 회원 홈의 일정·회의록·회비 요약 | 공개 홈 문구와 공개 활동 선정 방식 |
| 조직도 | 기수, 부서, 운영진, 역할 | 연락처 표시 범위와 수정 담당자 |
| 일정 | 제목, 시작·종료, 장소, 대상, 설명 | 누가 등록·수정할 수 있는지 |
| 회의록 | 날짜, 제목, 안건, 결정사항 | 열람 대상과 작성·수정 권한 |
| 프로젝트 | 담당자, 설명, 상태, 진행률 | 프로젝트 생성·참여·수정 방식 |
| 자료실 | 파일명, 분류, 작성자, 업로드 날짜 | 업로드 대상, 파일 종류·크기 |
| 사진 | 앨범, 행사, 사진, 촬영일 | 열람·업로드·삭제 범위 |
| 회비 | 학기, 회비 항목, 대상 회원, 금액, 납부 상태 | 입금 확인 절차와 회계 담당자 권한 |
| 정산 | 행사, 지출 항목, 금액, 참가자 | 참가자별 부담 기준과 반올림 방식 |
| 이벤트 | 행사, 대상자, 당첨 여부 | 선정 방식, 수정 권한, 공개 범위 |

## 먼저 작성할 명세: 일정 조회

- 사용자: 운영진에게 승인받고 로그인한 학회원. 내부 일정은 비회원과 승인 대기 이용자에게 공개하지 않습니다.
- 볼 정보: 제목, 날짜, 장소, 일정 설명.
- 동작: 월 이동, 날짜 선택, 일정 상세 열기.
- 없는 경우: 해당 날짜에 일정이 없다는 안내.
- 실패한 경우: 불러오기 실패 안내와 다시 시도.
- 완료 기준: 서버에서 받은 일정이 화면에 표시되고, 일정이 없는 경우와 오류도 구분해서 안내됩니다.

## 회원 기능을 만들기 전 결정할 사항

- 운영진은 입력받은 이름·학번을 어떤 기준으로 확인하나요?
- 로그인 식별자, 이메일 소유 확인, 이메일·학번 중복과 재가입 규칙은 어떻게 정하나요?
- 승인 대기·신청 반려·재신청을 어떻게 안내하나요?
- 학회원·운영진·회계 담당자를 어떻게 구분하나요?
- 졸업이나 탈퇴 시 접근 권한을 어떻게 바꾸나요?
- 개인 납부 내역은 로그인한 본인과 권한이 있는 운영진이 조회하도록 설계합니다.

기능 명세와 권한을 확정한 뒤 `docs/`에 DB 설계와 API 명세를 추가합니다.
