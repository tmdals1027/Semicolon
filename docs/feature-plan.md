# 기능 설계 초안

Figma의 스카이 블루 파스텔 페이지를 바탕으로 정리했습니다.
아래는 구현 목록을 논의하기 위한 초안이며, 권한과 세부 규칙은 아직 확정하지 않았습니다.

| 기능 | 화면에 필요한 정보 | 먼저 결정할 내용 |
| --- | --- | --- |
| 홈 | 다가오는 일정, 최근 회의록·사진, 회비 요약 | 로그인 전·후 공개 범위 |
| 조직도 | 기수, 부서, 운영진, 역할 | 연락처 표시 범위와 수정 담당자 |
| 일정 | 제목, 시작·종료, 장소, 대상, 설명 | 누가 등록·수정할 수 있는지 |
| 회의록 | 날짜, 제목, 안건, 결정사항 | 열람 대상과 작성·수정 권한 |
| 프로젝트 | 담당자, 설명, 상태, 진행률 | 프로젝트 생성·참여·수정 방식 |
| 자료실 | 파일명, 분류, 작성자, 업로드 날짜 | 업로드 대상, 파일 종류·크기 |
| 사진 | 앨범, 행사, 사진, 촬영일 | 열람·업로드·삭제 범위 |
| 회비 | 학기, 회비 항목, 대상 회원, 금액, 납부 상태 | 입금 확인 절차와 회계 담당자 권한 |
| 정산 | 행사, 지출 항목, 금액, 참가자 | 참가자별 부담 기준과 반올림 방식 |
| 이벤트 | 행사, 대상자, 당첨 여부 | 선정 방식, 수정 권한, 공개 범위 |

## 먼저 작성할 명세: 일정 조회

- 사용자: 미정 — 비회원 공개 여부부터 결정합니다.
- 볼 정보: 제목, 날짜, 장소, 일정 설명.
- 동작: 월 이동, 날짜 선택, 일정 상세 열기.
- 없는 경우: 해당 날짜에 일정이 없다는 안내.
- 실패한 경우: 불러오기 실패 안내와 다시 시도.
- 완료 기준: 서버에서 받은 일정이 화면에 표시되고, 일정이 없는 경우와 오류도 구분해서 안내됩니다.

## 회원 기능을 만들기 전 결정할 사항

- 가입은 누구나 가능한가요, 운영진의 승인이나 초대가 필요한가요?
- 학회원·운영진·회계 담당자를 어떻게 구분하나요?
- 졸업이나 탈퇴 시 접근 권한을 어떻게 바꾸나요?
- 개인 납부 내역은 로그인한 본인과 권한이 있는 운영진이 조회하도록 설계합니다.

기능 명세와 권한을 확정한 뒤 `docs/`에 DB 설계와 API 명세를 추가합니다.
