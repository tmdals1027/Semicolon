# 작업 방법

## 브랜치

- `main`: 실행 확인을 마친 기준 버전
- `chore/initial-setup`: 첫 프로젝트 세팅
- `feat/schedule-list`처럼 기능 하나마다 작업 브랜치를 만듭니다.
- 새 기능과 오류 수정도 작업 브랜치에서 진행하고 Pull Request로 변경 사항을 확인한 뒤 `main`에 합칩니다.

처음에는 `develop` 없이 시작합니다. 기능 하나를 완성하고 확인하는 흐름부터 익힙니다.

## 작업 순서

1. 이슈에 만들 기능과 완료 기준을 적습니다.
2. 최신 `main`에서 작업 브랜치를 만듭니다.
3. 변경한 기능을 직접 실행하고 관련 검사를 돌립니다.
4. 변경한 파일을 커밋하고 작업 브랜치를 깃허브에 올립니다.
5. Pull Request에서 변경 내용과 검사 결과를 확인한 뒤 합칩니다.

예시:

```text
feat: 일정 목록 조회 추가
fix: 일정이 없을 때 안내 표시
docs: 실행 방법 보완
chore: 프로젝트 초기 세팅
```

## 공통 규칙

- 파일은 UTF-8로 저장합니다. 프로젝트의 `.editorconfig`를 따릅니다.
- 프론트엔드 변경은 `npm run build`, `npm run lint`로 확인합니다.
- 백엔드 변경은 Gradle의 `test`, `bootJar`로 확인합니다.
- 동작이나 실행 방법이 바뀌면 관련 문서도 함께 수정합니다.
- 개인 정보, 실제 회비 내역, 비밀번호는 저장소에 넣지 않습니다. 예제는 가상 데이터를 사용합니다.
- 의존성을 바꾸면 `package-lock.json`이나 Gradle 설정도 같이 저장합니다.
- 실제 회원 데이터를 처리하는 기능은 로그인과 권한 검사까지 완료한 뒤 공개합니다.
